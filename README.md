# Aurora — мессенджер в стиле Telegram

Веб-мессенджер для телефонов: личные диалоги, группы, каналы с постами и комментариями,
истории на 24 часа, быстрые реакции, профили с баннером и личным каналом.
Бэкенд — Supabase (Auth + Postgres + Realtime + Storage), фронтенд — статика без сборки,
поэтому приложение загружается за пару секунд и работает на GitHub Pages.

Все иконки — inline SVG (никаких эмодзи в интерфейсе).

## 2. Быстрый старт (3 шага)

### Шаг 1. Применить схему базы

1. Откройте [SQL Editor](https://supabase.com/dashboard/project/xgruoaatkgfggqtkoorm/sql) вашего проекта.
2. Вставьте содержимое файла [`supabase/schema.sql`](supabase/schema.sql).
3. Нажмите **Run**.

Скрипт идемпотентный — его можно запускать повторно. Он создаёт таблицы, RLS-политики,
триггер создания профиля и личного канала, storage-бакеты и включает Realtime.

### Шаг 2. Настроить подтверждение email

**Authentication → Providers → Email**

- `Email confirmation` — **включить** (обязательно, иначе не будет экрана «Проверьте почту»).
- `Confirm email` / autoconfirm — **выключить**.

**Authentication → URL Configuration**

- `Site URL`: `https://<твой-юзер>.github.io/<твой-репозиторий>/`
- `Redirect URLs`: `https://<твой-юзер>.github.io/<твой-репозиторий>/**` и `http://localhost:**`

> **Про лимит писем.** Встроенный SMTP Supabase отправляет очень мало писем в час
> (на этом проекте лимит уже выбрал: `email rate limit exceeded`). Чтобы регистрация
> работала стабильно, подключите свой SMTP — например Resend (300 писем/месяц бесплатно):
> **Project Settings → Email → SMTP** (Host, Port, Username, Password, Sender).
> Свой SMTP не имеет таких жёстких ограничений.

### Шаг 3. Опубликовать

Приложение полностью статическое, собирать нечего.

**Вариант A — самый быстрый.** Залейте содержимое репозитория в ветку `main`,
затем `Settings → Pages → Build and deployment → Source: Deploy from a branch`,
ветка `main`, папка `/ (root)`.

**Вариант B — через Actions.** В репозитории уже лежит `.github/workflows/pages.yml`:
он публикует репозиторий как артефакт Pages. После добавления файла
`Settings → Pages → Source: GitHub Actions`.

Приложение использует хеш-роутинг (`#/chat/...`), поэтому перезагрузка страницы
на любом маршруте не даёт 404 и не требует rewrites.

## 3. Демо-режим

Пока схема не применена, приложение всё равно можно посмотреть: откройте
`https://<домен>/?mode=demo` (на главном экране есть кнопка «Открыть демо-режим»).

Демо-режим — это локальная база в браузере с тем же API, что и Supabase:
работают диалоги, группы, каналы, посты, комментарии, реакции, истории, регистрация
с подтверждением почты. Данные лежат в `localStorage` и никуда не отправляются.

Демо-аккаунты: `demo@aurora.app` / `demo12345` (пароль отображается на экране входа в демо-режиме).

### Свой Supabase-проект

Откройте `assets/js/config.js` и замените значения (или задайте `window.AURORA_CONFIG`
в `index.html` до подключения скрипта):

```js
supabase: {
  url: 'https://<ref>.supabase.co',
  key: 'sb_publishable_...',   // publishable-ключ, он публичный по умолчанию
}
```

## 5. Про ключи Supabase

Ключ, который вы прислали — **publishable** (новый формат `sb_publishable_...`).
Он специально предназначен для браузера: его можно вшивать в клиентский код, он даёт
права только на публичные операции (чтение таблиц под RLS, регистрация, вход).
Секретный ключ (`sb_secret_...` / service_role) в клиентский код попадать не должен —
он обходит RLS. В проекте он не нужен: вся авторизация и RLS живут на стороне Postgres.

`publishable` vs `anon`: для SPA на клиенте Supabase рекомендует publishable-ключ —
он безопаснее (нельзя отключить RLS флагом) и не требует отдельного `apikey`-заголовка.

## 6. Что осталось от телеграма (следующий заход)

Реализовано всё, что видно в интерфейсе. Не сделаны пока:

- **Звонки** — нужны WebRTC + TURN-сервер (в интерфейсе есть кнопка вызова).
- **Push-уведомления** — нужен Web Push / Service Worker (тогглы в настройках есть).
- **Избранное, поиск по чату, стикеры и GIF, опросы, таймер автоудаления сообщений** — сейчас заглушки.
- **Веб-версия Telegram (Web K)** как референс — этот клиент нативно-подобный, с бургер-меню и голосовыми.

Готов продолжать в эту сторону — скажи, с какого пункта начать.

## 7. Безопасность

- RLS включён на всех таблицах, доступ к чатам проверяется функцией `is_member()`.
- Политики на запись: сообщения и посты создаёт только их автор, реакции — только за себя.
- Storage-бакеты публичные на чтение, на запись — только авторизованным.
- Триггер `handle_new_user` создаёт профиль и личный канал автоматически.
- Клиент не содержит секретов: только publishable-ключ.
